# Unified PDF Toolkit v0.6.0-beta.4

This controlled beta introduces a managed, consent-gated local deployment path
for `baidu/Unlimited-OCR`. The default application remains lightweight: model
weights, PyTorch, Transformers, and CUDA runtime packages are not bundled.

## Highlights

- Environment Inspector for operating system, CPU, RAM, GPU/VRAM, NVIDIA
  Driver, CUDA, Python, environment managers, storage, GUI, and Basic OCR.
- Metadata-driven Compatibility Engine with explicit supported, experimental,
  unknown, and unsupported decisions instead of a GPU-present boolean.
- Informed consent bound to the exact plan, metadata, model revision, private
  runtime, dependency set, and selected GPU.
- Isolated uv-managed AI runtime with pinned dependencies; no global Python,
  PATH, Driver, or system CUDA modification.
- Fixed model revision, required-file inventory, size checks, and SHA-256
  verification before custom model code is loaded locally.
- Resumable staged installer with progress, cancellation, retry, recovery,
  installer locking, corrupt-journal handling, diagnostics, and bounded cleanup.
- `UnlimitedOCRProvider` integration with a persistent private worker, health
  checks, structured errors, and explicit Basic OCR fallback boundaries.
- Deterministic multi-GPU selection with plan/consent identity and worker
  isolation bound to the selected NVIDIA GPU UUID.
- CLI and GUI inspection, planning, setup, status, uninstall, and cleanup flows.
- PyInstaller support for compatibility metadata and private-runtime worker
  entrypoints installed after consent.

## Verified devices

### Windows with RTX 3060 12 GiB

Real private installation, model verification/load, five-layout OCR,
benchmark, repeated inference, and cancellation/recovery passed. The existing
Tesseract executable remains available as Basic OCR fallback on this device.

### Ubuntu with dual RTX 4090

Real private installation, selected-GPU UUID binding, model verification/load,
five-layout OCR, benchmark, 50-request stability, cancellation/recovery, and
setup idempotency passed. The second GPU remained unused. Tesseract is not
installed on this device, so a working Basic OCR fallback is not claimed.

### Ubuntu with GTX 1060 6 GiB

The normal APP and CLI run successfully, while Unlimited-OCR is correctly
classified as unsupported by the VRAM, GPU architecture, and RAM gates. Even
with every acknowledgement supplied, setup stops before creating managed state;
no model or AI runtime was downloaded.

These results are device-specific evidence for the pinned revision. They are
not a support claim for every NVIDIA GPU or every Linux installation.

## Safety boundaries

The managed flow does not automatically:

- update the NVIDIA Driver;
- install, replace, remove, or add a system CUDA Toolkit to PATH;
- modify system Python, Conda base, shell profiles, or global site-packages;
- download the multi-gigabyte model before exact-plan informed consent;
- force setup on an unsupported or unknown device;
- upload documents, page images, OCR output, or hardware reports.

Pinned third-party custom model code still carries supply-chain risk. It runs
only from the verified local snapshot in the isolated private worker, but this
does not eliminate the risk.

## Known limitations

- The verified dual-RTX Ubuntu device has no Tesseract executable.
- The rotated synthetic OCR case currently matches 1 of 2 expected tokens.
- Fifty requests are useful stability evidence, not a long-duration soak.
- No intentionally dangerous real GPU exhaustion test was performed; OOM
  behavior is covered through bounded failure injection.
- A real network interruption during model-download resume has not yet occurred.
- There is no multi-GPU model sharding or automatic GPU failover.
- Apple Silicon remains `EXPERIMENTAL CANDIDATE / NOT_TESTED`.
- AMD and CPU-only Unlimited-OCR execution are not formally supported.
- OCR accuracy, latency, and freedom from OOM cannot be guaranteed on untested
  documents or hardware.
